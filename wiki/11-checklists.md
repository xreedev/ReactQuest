# 11 — Checklists

## A. CV self-audit

- [ ] Single column, text-based PDF (+ .docx variant kept), one page, standard headings
- [ ] Profile title is literally the job title you want
- [ ] Summary contains years + React + TypeScript + Redux + domain in the first two lines
- [ ] Skills block has versions and covers every token in your 3 target JDs — and nothing you can't defend
- [ ] Every experience bullet: verb + decision + measurable or concrete outcome
- [ ] Ran every bullet through XYZ; no `[Y: ___]` placeholders left unresolved (found the number, or deleted the claim)
- [ ] At least 4 bullets that deliberately bait questions you've prepared (re-renders, Redux optimisation, API cancellation, code splitting)
- [ ] "React.js / ReactJS" and city synonyms present somewhere
- [ ] Backend / full-stack exposure listed if genuine
- [ ] No photo, no skill bars, no tables, no two-column layout
- [ ] Projects: none stale, none unmaintained, none you can't demo
- [ ] Nothing on the page you'd be uncomfortable being asked about for ten minutes

## B. Naukri / LinkedIn audit

- [ ] Headline ≤60 chars: role + years + stack + city
- [ ] IT Skills section filled with versions and experience levels
- [ ] Current CTC, expected CTC, notice period, preferred locations all filled
- [ ] Status set to "Actively looking"
- [ ] Uploaded resume is the single-column ATS version
- [ ] Profile touched at least weekly during an active search
- [ ] LinkedIn headline matches Naukri headline
- [ ] Referral paths identified at 2–3 target firms

## C. Interview readiness (per Must-Know node)

- [ ] Answer any JS output question in under 60 seconds, with reasoning
- [ ] Explain why a given component re-rendered — and fix it
- [ ] Build fetch + render + loading/error/empty + debounced input, live, in 20 minutes, narrating
- [ ] Draw Redux flow from memory
- [ ] One-sentence Context-vs-Redux decision rule
- [ ] Five Redux optimisation levers, named
- [ ] Design a three-screen app live: routes, auth boundaries, state placement, parallel API calls, error handling
- [ ] HTML/CSS trivia recovered instantly (semantic tags, void elements, display vs visibility, pseudo-class vs pseudo-element)
- [ ] Write debounce, throttle, deep clone, flatten from memory
- [ ] Three Git incident answers (revert pushed commit, stash/branch switch, merge conflicts)
- [ ] TypeScript: type props, hooks and events; explain `unknown` vs `any`
- [ ] Jest/RTL: write one meaningful test; explain unit vs integration vs e2e
- [ ] 90-second project story ending in a decision and its tradeoff
- [ ] 10-minute project deep-dive with architecture

## D. Day-before, per company

- [ ] Re-read that company's block in `04-question-bank.md`
- [ ] Check the *adjacent gate* for that company in `01-market-and-loop.md` (Infosys → HTML/CSS; Wipro → Java; IBM/Deloitte → Next.js + testing; Accenture → JS internals + Git)
- [ ] Re-read your own CV and pre-answer the follow-up for every line
- [ ] Rehearse: why leaving · notice period · relocation · agile experience
- [ ] Have one question ready to ask them about the project/account

## E. In-round rules

- [ ] Answer exactly what was asked; don't volunteer extra surface
- [ ] Frame answers as tradeoffs: option A vs B, and the condition that decides
- [ ] Say "I haven't used that" cleanly instead of bluffing
- [ ] In machine coding: restate the MVP aloud before writing any code
- [ ] Build behaviour before polish
- [ ] Narrate what you'd add next when time runs out

## F. Post-rejection triage

- [ ] Did I fail *in* a round, or never get feedback? (Only the first is a study problem)
- [ ] Which node from `02` did I actually miss?
- [ ] Was it a breadth gap (one blank) or a depth gap (collapsed on follow-up)?
- [ ] Was it a résumé–JD mismatch discovered mid-interview?
- [ ] Was it CTC band, level, or notice period? (Not fixable by studying)
- [ ] Update `04` with the questions you were actually asked
